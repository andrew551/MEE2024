# MEE v1.3.9

Windows executable, no Python installation required. Double-click for the app window, or run
it from a terminal for the command line; the classic interface is still there with
`MEE_v1.3.9.exe gui`.

**This is the first release since v1.3.5.** v1.3.6, v1.3.7 and v1.3.8 were each built and
tested in the field but never published, so everything they carried is here.

---

## The program is now called MEE

`MEE2024` was named before the 2024 eclipse. The same code reduces 2017, 2024 and 2026 data
and prepares for 2027, so the year described one dataset rather than the software. The
executable is now **`MEE_v<version>.exe`** and the window title is **MEE**.

Nothing else moves. The repository, the Python package, the `mee2024` command, your settings
file and the `MEE2024` FITS provenance keyword all keep their names — so existing clones,
scripts, installed catalogues and pattern databases carry on untouched, and no archive is
re-downloaded.

---

## If you are coming from v1.3.5, four things first

- **Your batch output no longer overwrites itself.** In v1.3.5 a second run pointed at the
  same output folder silently destroys the first run's summary and log.
- **Successful command-line runs no longer exit with code 1.** In v1.3.5 every scripted run
  reports failure to the shell whatever it actually did, so `mee2024 stack ... && next-step`
  never ran the next step.
- **There is a calibration library.** Build master darks and flats once; each field is matched
  to the tier that fits its own frames, and the match is reported per field.
- **SER files are read directly**, with no conversion and no second copy of a 15 GB file.

## New in v1.3.9

Every item here either adds information or changes a message. **Nothing changes a measured
number**, which is what makes this the field-tested v1.3.8 with the name changed.

- **The float32 stack is always written, and now has a header.** It used to appear only if a
  classic-UI checkbox was ticked — off by default, absent from the app window and the CLI —
  and it was written with no header at all: no version, no exposure, not even the frame count.
  The one output holding the calibrated values with no pedestal and no rounding was also the
  one that could not say where it came from. The checkbox is gone; the file is always there.
- **Stacked frames carry their own provenance.** `EXPTIME`, `GAIN`, `EGAIN`, `OFFSET`,
  `CCD-TEMP`, `DATE-OBS`, camera and optics, plus `CALDARK`, `CALFLAT` and `CALHOT` saying
  which master dark and flat were applied and how many hot pixels were excluded. Both
  calibration keys are written always, with an explicit `none` — absence of a keyword is not
  evidence of absence of a dark.
- **Masters record `DATAMIN`/`DATAMAX`.** A master is exactly the file someone opens in a
  viewer that would otherwise autoscale to the hottest pixel, and the range answers without
  loading the array whether a flat is normalised (max near 1) or raw ADU.
- **The flat exposure check now runs on flats you pick by hand.** It only ran when a library
  was *built*, which left the commonest case unchecked. A flat outside 25–75% of full scale is
  reported: mid-range fill is what makes it safe to take no flat-darks, and the residual
  pedestal's share grows as the fill falls.
- **A calibration library defaults to `CALIBRATION_LIBRARY` inside your output folder**, and a
  build no longer refuses to start without a path. Derived data does not go in the capture
  tree; the library path is still remembered separately, so a library built once is reused
  rather than rebuilt per output folder.
- **The app window has its own settings file, and no longer writes yours.** This is a real
  bug, not tidying: the app window *wrote* `sensitive_mode_stack`, `distortionOrder`,
  `distortion_fit_tol`, `max_star_mag_dist`, `guess_date` and the folder paths into
  `MEE_config.txt` — the file the classic UI and the CLI read — while never reading that file
  itself. Running the app window once on the "quick" preset left `sensitive_mode_stack: false`
  waiting for your next classic-UI session, with nothing to show it had happened. It now keeps
  `MEE_app_config.txt`, seeded once from your existing settings so nothing you chose is lost.

The rule behind that last one: **an interface should only apply settings it can show.** The
classic UI displays forty-odd options and the app window eight, so a shared file guarantees
one of them runs on values you cannot see where you are working.

## Fixed since v1.3.5

- **Batch output overwriting itself.** `batch_summary.csv`, `batch_summary.json` and
  `activity.jsonl` were written straight into the output folder, so a second run destroyed the
  first run's records — the very files that say what happened. Each run now writes into a
  subfolder named for its input, timestamped only if records are already there.
- **The records a run writes were unreachable.** Everything was on disk and nothing in the
  window opened any of it. "Open output folder" now points at the run root and appears whether
  the run succeeded, failed or was cancelled; every row of the batch table opens that field's
  folder. Each field folder carries its own `field_summary.json` and log slice — failed fields
  too, since the absence of a folder is not a diagnosis.
- **Successful CLI runs exited with code 1**, because the commands return the archive they
  wrote and `sys.exit()` treats a non-integer as an error message.
- **A capture path with an unusual character could kill a run mid-flight** — the log was
  opened in the platform encoding and writes the frame list verbatim.
- **Taking more darks silently masked more pixels.** The defect threshold was a multiple of the
  master's own noise, which falls as 1/√N: 20σ measured 5.3 ADU with 50 darks against 8.7 ADU
  with 10, so a longer calibration run changed which stars reached the fit. There is now a
  10 ADU floor, which can only mask fewer pixels than before, never more.
- **A pedestal warning that fired on every correctly calibrated frame.** It waits until more
  than 1% of the frame is negative — what a genuinely mismatched dark looks like.
- **Darks and flats picked in single mode leaked into folder runs**, applied to every field
  invisibly with no way to see or clear them.
- **A stray file in a session root swallowed the tree**: a folder holding one photograph beside
  the real capture tree was claimed as the only field.
- **The observation epoch is now decided where the data is**, not in one front end's options
  assembly; the CLI no longer falls back to a 2023 default. `--date`, `--date-from-header` and
  `--guess-date` join the command line, and a date disagreeing with the frames is reported.
- Pattern databases are released before a rebuild; the classic dialogs no longer open wherever
  Windows launched the executable from; a leaked log handle in the catalogue reader (found by
  Douglas); and a "pixels were clipped" warning that could never fire and would have been
  wrong if it had.

## Also new since v1.3.5

- **Several folders at once in batch mode** — Ctrl-click, or select rows in the picker.
- **Choosing which frames to use without making a copy**: `--frames 50-172` is a run
  parameter, and a scan suggests a usable range.
- **A frame that lies about its exposure is reported.** Capture software can write a new
  exposure into the header of a frame that still holds the previous one; six frames of the
  León ladder do. It reports rather than corrects.
- **Master darks and flats carry provenance** — exposure, gain, offset, both temperatures,
  camera, optical train and source folder.
- **The 2-D residuals are saved as `TWOD_RESIDUALS.csv`**, not only drawn into a PNG.

## Measured, and not yet acted on

From the León campaign, in `docs/LEON_2026-08-11.md`. These are the reason for v1.4.0:

- **The eclipse was 9.7° above the horizon**, where the curvature of vertical refraction
  across the field — the part neither the plate solve nor the fit's linear terms absorb — is
  **0.50″**, about 4× what these fields actually fit. Refraction correction is still off by
  default and unreachable from the app window.
- **FITS site coordinates cannot be trusted**: 17.8 km wrong in this set, pointing at the
  nearest city, with no altitude keyword at all. Check yours against your own site record.
- **Read noise measures 25–30% below the header's `RDNOISE`** at both gains, consistently.
- The site ran at **895–898 hPa** against a pipeline default of 1010; with the unmodelled
  1101 m of elevation the defaults overstate refraction by 15.7%.
- The plate scale predicted from `FOCALLEN` and `XPIXSZ` agrees with the fitted value to
  **0.45%**, making it a usable prior for the solver.

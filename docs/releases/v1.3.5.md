Windows executable, no Python installation required. Double-click for the app window, or run it from a terminal for the command line; the classic interface is still there with: `MEE_2024_v1.3.5.exe gui`.

A maintenance release. Nothing here changes how a fit is computed, but two of the fixes are worth reading if you use the astrometric corrections or the deep catalogue.

### Fixed

- **A failed astrometric correction could silently disable gravitational light deflection for the rest of the session.** `correct_ra_dec` patches erfa's deflection routine and restored it only on success, so any exception in between — a malformed observation date is enough — left every later astropy calculation running with the deflection zeroed, with no warning. For an experiment that exists to measure that deflection, this was the worst available failure mode.
- **Log files stayed locked until the program closed.** Each run's `LOG*.txt` was held open for the life of the process, so it could not be moved or deleted while the app was running, and the handles accumulated one per run. A failed run now releases its log too, which is when you actually want to read it.
- **Four star names were attached to the wrong stars.** Schedar was on γ Cassiopeiae, Castor on Miaplacidus, Alphard on Suhail, and Thuban on Kochab. Every name is now verified against the star's real position, and the list has grown from 50 to 128 IAU names — Alderamin among them, which is what prompted the check.
- **The file and folder pickers shared one memory**, so choosing an output folder re-aimed the next input dialog and vice versa. Each now remembers its own.
- **A newly downloaded catalogue stayed invisible until the program was restarted.** The catalogue list is now re-read as soon as a download lands.
- **A file pattern matching nothing** failed with an OpenCV assertion instead of naming the file it could not open.

### Changed

- **The observation date is now read from the FITS header by default**, falling back to recovering it from proper motions when the frames carry no date. The header is a measurement; recovery is honest to two to four weeks.
- **Stars with a close companion are dropped from the distortion fit by default.** A blended pair gives a systematically wrong position rather than a noisy one. This matches the app and the command line, so the same frames give the same answer either way. Existing settings are untouched — only fresh installs change.
- **A download over 1 GB now asks first**, quoting the exact size and the disk it needs, and says plainly that the standard `gaia_dr3_g13` archive is enough for ordinary work. A run will never start a download that large on your behalf.
- **Installed catalogues can be removed from inside the app**, freeing the disk without closing the program.
- **The superseded `gaia_dr3_g12` archives are no longer offered as choices** — `gaia_dr3_g13` already contains those stars. If you still have them, the app offers once to clear them out.

### New

- **`gaia_dr3_g15` is published**: Gaia DR3 to G < 15, 36,909,335 stars, for work that needs stars fainter than G = 13. It is a 1.57 GB download and needs about 3.5 GB of disk while it installs, so most users should stay on `gaia_dr3_g13`. Install it with `mee2024 catalogue --fetch gaia_dr3_g15`.

### Note on earlier releases

The `v1.0.1`, `v1.3.1` and `v1.3.4` tags pointed at the wrong commit and have been corrected — checking out any of them previously gave source predating v1.0.0. The `main` branch now carries the current code, so future tags follow it.
